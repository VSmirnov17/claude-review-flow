# claude-review-flow

Created in [T3 Code](https://t3.codes).

Плагин для Claude Code, который переносит в любой GitHub-проект схему ревью из статьи [How we solved code review at Anthropic](https://claude.dev/blog/solving-code-review-at-anthropic/): машины проверяют каждый PR, а люди подключаются в зависимости от риска.

## Как устроен флоу

```text
локально     /review-flow:pre-pr     проверки с выводом, ревью и security в свежем контексте, описание PR
                  |
каждый PR    review-flow.yml         охотники за багами -> голосование -> inline-комментарии
                                     security-ревью -> голосование -> inline-комментарии
                                     два классификатора -> tier и нужен ли человек
                  |
merge        review-flow/gate        tier = max(решение модели, правила путей) -> нужное число людей
             защита ветки            открытый finding блокирует, CI, ветка актуальна
                  |
после        /review-flow:evals      инцидент -> проверенный кейс -> оценка ревьюера
             /review-flow:metrics    время людей, а доля откатов как ограничитель
```

## Что входит

| Тип | Файл | Назначение |
|---|---|---|
| Агент | `agents/bug-hunter.md` | Ищет баги с одного заданного угла |
| Агент | `agents/finding-verifier.md` | Независимо голосует за каждую находку |
| Агент | `agents/security-reviewer.md` | Ищет уязвимости с прослеживаемым путём атаки |
| Агент | `agents/risk-classifier.md` | Определяет tier только по изменению |
| Агент | `agents/human-need-checker.md` | Решает, нужен ли человек сверх tier |
| Скилл | `/review-flow:setup` | Устанавливает схему в текущий репозиторий |
| Скилл | `/review-flow:pre-pr` | Готовит изменение к PR |
| Скилл | `/review-flow:review` | Ревью: `quick`, `standard` или `deep` |
| Скилл | `/review-flow:security` | Отдельное security-ревью |
| Скилл | `/review-flow:classify-risk` | Оценка риска изменения |
| Скилл | `/review-flow:address-findings` | Разбор открытых тредов в PR |
| Скилл | `/review-flow:evals` | Кейсы из инцидентов и оценка ревьюера |
| Скилл | `/review-flow:metrics` | Метрики времени людей и откатов |
| Правила | `skills/setup/templates/claude/rules/review-flow.md` | Постоянные правила для агента в проекте |
| Шаблоны | `skills/setup/templates/` | `REVIEW.md`, `CLAUDE.md`, шаблон PR, CODEOWNERS, политика, workflow |

Плагины Claude Code не поставляют `.claude/rules/`, поэтому правила копирует в проект скилл `setup`.

## Установка

1. Опубликуйте этот репозиторий на GitHub. Он должен быть публичным, иначе CI понадобится доступ к приватному репозиторию.
2. Подключите плагин:

   ```bash
   claude plugin marketplace add <owner>/<repo>
   claude plugin install review-flow@review-flow
   ```

3. В нужном проекте запустите `/review-flow:setup`. Нужен установленный и авторизованный [`gh`](https://cli.github.com/). Скилл покажет план и ничего не перезапишет без подтверждения.
4. Выполните шаги, которые `setup` оставит вам: секрет, GitHub App и merge файлов в основную ветку, а затем включите защиту ветки.

## Как проходит одобрение

| Tier | Людей по умолчанию |
|---|---|
| low | 0 |
| medium | 1 |
| high | 2 |

- Если изменение затрагивает пути из `always_human`, классификатор потребовал человека или автора нет в `trusted_authors`, нужен минимум один человек.
- Одобрение действует только для конкретного коммита.
- Человек из `trusted_authors` может взять ответственность комментарием `/signoff <sha>`. Так автор или тот, кто направлял агента, считается одним из нужных людей. GitHub не даёт одобрить собственный PR, поэтому без этой команды соло-разработчик не прошёл бы гейт.
- `/recheck` пересчитывает гейт.

Всё настраивается в `.github/review-flow/risk-policy.json`, режим ревью задаётся переменной репозитория `REVIEW_FLOW_MODE`.

## Отличия от статьи

В статье нет этих деталей, поэтому значения выбраны здесь. Подстраивайте их по результатам `/review-flow:evals`.

- Число охотников и порог голосов: таблица в `skills/review/SKILL.md`.
- Полное ревью идёт только в первом раунде, дальше проверяется только новый diff. В статье это начинается «после первых нескольких проходов».
- Лимит раундов останавливает ревью багов, а security-ревью продолжает работать. После лимита каждому новому коммиту нужен человек.
- Статья допускает повторное использование одобрения для коммитов, которые система может проверить. Здесь любой новый коммит сбрасывает одобрение.

## Ограничения

- `always_human` требует какого-то человека, а не конкретного владельца. `CODEOWNERS` здесь только назначает ревьюеров.
- Коммит-статус может подделать любой с правом записи, например изменённым workflow в своей ветке. Гейт защищает от ошибок и от содержимого PR, но не от недобросовестного участника с правом записи. Внешним участникам используйте форки.
- Запрет на `/signoff` и одобрение для агента задан в `.claude/settings.json` и работает только в Claude Code. Агент с вашими токенами в другом окружении так не ограничен.
- Force-push убирает старые коммиты, и счётчик раундов может начаться заново.
- Merge queue доступна только репозиториям организаций. Для личных репозиториев защита ветки требует актуальности ветки (`strict`), что даёт ту же гарантию ценой последовательных merge.
- Защита ветки в приватном репозитории требует платного плана GitHub.
- Модель может ошибиться с tier из-за содержимого PR. Поэтому она способна только повысить tier относительно правил путей, но не понизить его. Заполните `floors` и `always_human` под свой проект.
- CI запускает три прохода Claude на каждый push, поэтому начните с одного репозитория и смотрите на расход.
